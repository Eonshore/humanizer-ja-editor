# 作者プロファイル

humanizerの目標は「人間一般の平均」ではなく、対象となる書き手の分布へ戻すことである。

## 使用条件

作者サンプルとして使うのは、次のいずれかに限る。

- ユーザー本人の文章
- ユーザーが編集権限を持つ組織文書
- 使用許可のあるスタイルガイドやサンプル
- パブリックドメインなど、利用条件を満たす資料

特定人物への成りすましや、作者性の偽装を目的にしない。出力を本人執筆と主張しない。

## 必要なサンプル量

- 最低: 2〜3段落
- 推奨: 同じ用途の文章3〜10本
- 長文: 合計2,000〜10,000字程度

一つの短文だけでは、偶然の表現と恒常的な癖を区別しにくい。サンプルが少ない場合は暫定プロファイルと扱う。

## サンプル選定

できるだけ対象文書と同じ場面を選ぶ。

- ブログを直すならブログ
- 技術文書を直すならREADMEや設計文書
- 小説を直すなら同一作品か同一視点
- チャットを直すなら実際のチャット

異なる場面を混ぜる場合、場面別に分けて読む。

## 観察項目

### 文と段落

- 平均だけでなく短文・長文の幅
- 一段落の文数
- 一文段落の頻度
- 段落冒頭と末尾のパターン
- 改行の密度

### 語尾

- 敬体 / 常体
- `です`、`ます`、`だ`、`である`
- `と思う`、`と考える`、`かもしれない`
- 体言止め
- 疑問形、余韻、言いさし

### 語彙

- 漢語、和語、カタカナ語の比率
- 専門語の説明方法
- 同じ語を繰り返すか、言い換えるか
- よく使う接続表現
- 評価語と確度表現

### 記号

- 「」『』（）、ダッシュ、三点リーダー
- 読点の密度
- 感嘆符、疑問符
- Markdown見出し、太字、箇条書き

### 語りの立場

- 一人称
- 読者への呼びかけ
- 断定と留保
- ユーモア、皮肉、自省
- 反論や例外の扱い

### 構造

- 先に結論を置くか
- 具体例から始めるか
- 見出しの粒度
- 要約や結論を置くか
- 脱線や補足の位置

## 定量化スクリプト

```bash
python scripts/profile_author.py samples/*.md --output author-profile.json
```

出力例は `assets/author-profile.template.json` を参照する。

スクリプトは次を集計する。

- 文字数、文数、段落数
- 文長と段落長の分布
- 語尾の頻度
- 接続表現の頻度
- 一人称と読者呼称
- 括弧、ダッシュ、三点リーダー、感嘆符など
- Markdown構造

形態素解析を行わないため、語彙の意味分類や精密な品詞比率はモデルが原文を読んで補う。

`profile_author.py` が扱うのは、文長、語尾、記号、接続表現などの定量的な声の手掛かりである。
読者に何を理解してほしいか、どの問いから始めるか、どの抽象度でコードを見せるか、どの証拠を本文へ置くかといった意味的な説明戦略は推定しない。
リポジトリやコードから技術説明を作る場合は、この定量プロファイルを説明戦略の根拠にせず、[ソフトウェア解説の説明プロファイル](software-exposition.md#説明プロファイル) を別に作る。

## 優先順位

複数の指示が衝突した場合は次を優先する。

1. ユーザーの明示指示
2. 投稿先・組織・作品の正式スタイルガイド
3. 同じ場面の作者サンプル
4. このスキルの場面プロファイル
5. 一般的なAIパターン規則

たとえば作者サンプルがダッシュを頻繁に使うなら、一般規則だけを理由に全削除しない。

## 適用方法

### 保持する癖

- 意図的な反復
- 固有の語尾
- 括弧や改行の使い方
- 迷いや自訂正
- 特定の専門語
- 非対称な段落構成

### 補正する癖

作者サンプルにも存在していても、次は編集対象になりうる。

- 事実誤認
- 文書の用途を壊す曖昧さ
- 誤読を生む係り受け
- 誤字脱字
- 今回の依頼で明示された改善点

「作者が使う」ことは、すべての誤りを残す理由ではない。

## 作者プロファイルから新しい人格を作らない

サンプルに一人称があるからといって、元文に新しい体験を足さない。語尾、リズム、語彙選択は寄せられるが、内容上の自己開示は捏造しない。

```text
許容: 「〜と考えられる」を作者が使う「〜だと思う」へ変更する
禁止: 「私も以前この問題で失敗した」を追加する
```

## 過学習防止

- 特徴を一文ごとに詰め込まない
- 口癖を原文以上の頻度で使わない
- サンプル中の偶然の誤字を再現しない
- 一つの印象的な文をテンプレとして繰り返さない
- 内容より文体模倣を優先しない

作者らしさは複数の弱い特徴の組み合わせとして再現する。

## 資料の役割を混同しない

作者サンプルは、対象文書の語調、段落、用語の説明方法を選ぶための資料である。
別のリポジトリや技術分野で書かれた作者サンプルから、対象の実装、到達可能な振る舞い、テスト結果、性能、運用状態を読み取らない。

同じ資料を作者の声と事実の根拠へ使うのは、その資料が対象そのものについて信頼できる根拠を持ち、かつ声を合わせることもユーザーの意図に合うと明示できる場合だけにする。
説明構造だけを借りる資料は、事実の根拠にしない。
