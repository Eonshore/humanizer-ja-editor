# 誤修正境界

## 直すべき例

### 空の重要性

```text
変更前: この変更は、開発体験の進化において極めて重要な一歩です。
原文にある情報: ビルド時間が12分から4分へ短縮
変更後: この変更で、ビルド時間は12分から4分へ短縮しました。
```

数字が原文にない場合は追加しない。

### 無源引用

```text
変更前: 多くの研究によると、この方法で生産性が40%向上します。
安全な処理: 出典を確認するまで、この論断を削除または要確認にする。
危険な処理: この方法で生産性が向上します。
```

出典句だけを消して、依存する結論を裸の事実として残さない。

### 主体の入れ替わり

```text
変更前: ベンダーがパッチを作成し、当社が検証した。
危険: 当社がパッチを作成して検証した。
```

### 可能性の断定化

```text
変更前: メモリ断片化が原因の可能性がある。
危険: 原因はメモリ断片化だ。
```

### 同義反復

```text
変更前: レスポンスは320msから180msへ短縮した。これは応答速度が改善したことを示す。
変更後: レスポンスは320msから180msへ短縮した。
```

## 直してはいけない例

### 機能的な箇条書き

```text
- `timeout`: 秒単位のタイムアウト
- `retries`: 再試行回数
- `backoff`: 再試行間隔
```

太字ラベルや三項並列に見えても、APIリファレンスとして機能しているため残す。

### 学術的な限定

```text
本結果は、対象群が単一施設に限られるため一般化できない可能性がある。
```

「可能性」「限られるため」を冗長と判断して消さない。

### 法務上の限定

```text
本資料は法的助言を構成するものではありません。
```

一般的なチャット残骸に似ていても、文書目的上必要なら残す。

### 意図的な反復

```text
彼女は待った。雨が止むのを待った。誰かが戻るのを待った。
```

小説のリズムなら統合しない。

### 作者固有のダッシュ

作者サンプルが一貫してダッシュを使い、意味上も機能する場合は残す。記号単体をAIパターンと決めつけない。

### 技術的なシステム主語

```text
ロードバランサーがヘルスチェックに失敗したノードを除外する。
```

モノに人間の動詞をさせるfalse agencyではない。システムの実際の動作である。

## 場面で判断が変わる例

### 「本稿」

- 学術論文: 通常は保持
- 個人ブログ: 場面に合わなければ「この記事」または削除
- 小説: メタフィクションでなければ不自然な可能性

### 節番号

- 仕様書、論文、提出レポート: 保持
- 300字のSNS投稿: 過剰な構造なら削除

### 丁寧語の均一性

- 顧客向け通知: 一貫性が必要
- 個人エッセイ: 作者サンプルに揺れがあれば再現可能
- チャット: 元の距離感を優先

### 接続詞

- 逆接や因果を明示する一語: 保持
- 各段落冒頭の「さらに」「加えて」: 削減候補

### 一人称

- 元文または作者サンプルにある: 保持、語尾を寄せられる
- 元文にない: 人間味のために追加しない
- レポート規定で禁止: 削除または非人称表現へ

## 長さに関する境界

文章が短くなること自体は失敗ではない。空の前置き、同義反復、結論の儀式を削れば自然に短くなる。

一方、次を失って短くなった場合は失敗である。

- 数字
- 条件と例外
- 反論
- 確度
- 根拠
- 時間順序
- 責任主体
- 作者固有の具体的描写

## 作者サンプルの境界

作者サンプルは表現仕様であり、内容の供給源ではない。

```text
サンプルの特徴: 「〜だと思う」を多用
対象文: この方式は有効と考えられる
許容: この方式は有効だと思う
禁止: 私も実際に使って有効だと思った
```

## AI判定との境界

このスキルの診断項目は文章編集のためのもの。次の主張には使わない。

- この文章はAI生成である
- この学生は不正をした
- この応募者は文章を書いていない
- このスコアなら人間の文章である

整った文章や特定表現だけでは作者性を判定できない。
