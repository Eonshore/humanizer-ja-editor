# 編集操作

## 編集範囲

### minimal

許可:

- 句読点と空白の調整
- 接続詞、評価語、前置きの局所削除
- 名詞化を動詞へ戻す
- 一文の分割または結合
- 語尾の局所的な調整

禁止:

- 意味のある文の削除
- 段落の並べ替え
- 見出し構造の変更
- 新しい例や意見の追加

### bounded

minimalに加えて許可:

- 情報を持たない一文の削除
- 同義反復の統合
- 小さな段落の統合・分割
- 機能しない見出しの削除

禁止:

- 論証順序の大幅な変更
- 実質情報の圧縮
- 作者の立場の再構成

### structural

boundedに加えて許可:

- 段落の並べ替え
- 導入と結論の再構成
- 見出し体系の変更
- 複数段落の再編集

条件:

- ユーザーが構成改善を求めている
- 事実台帳を作成済み
- 編集後に保真監査を行う

## 推奨する操作

### 宣言を内容へ置き換える

```text
変更前: ここではキャッシュの仕組みを詳しく説明します。
変更後: このキャッシュはリクエスト単位とルート単位の二層で動きます。
```

後半の具体情報が原文にある場合だけ置き換える。なければ宣言を削除するだけにする。

### 名詞化を動詞へ戻す

```text
変更前: 設定の変更を実施します。
変更後: 設定を変更します。
```

```text
変更前: 性能の改善を実現しました。
変更後: 性能が改善しました。
```

誰が改善したかが明示されている場合は、その主体を残す。

### 単純な動詞を使う

```text
変更前: 展示空間として機能しています。
変更後: 展示空間です。
```

ただし「機能する」が技術用語として意味を持つ場合は変えない。

### 同義語の輪番を止める

```text
変更前: この取り組みは成果を上げた。本施策は全社へ展開される。このイニシアチブは来月始まる。
変更後: この取り組みは成果を上げた。来月から全社へ広げる。
```

同じ対象には、最も明確な語を繰り返してよい。

### 抽象的な再説明を削る

```text
変更前: p95は480msから160msへ下がった。これは性能改善の重要性を示している。
変更後: p95は480msから160msへ下がった。
```

二文目に独自の判断や条件がある場合は残す。

### 接続を文順で示す

```text
変更前: また、テストは成功しました。さらに、メモリ使用量も減りました。
変更後: テストは成功し、メモリ使用量も減りました。
```

接続詞を全部消すのではなく、関係を明示する必要がある箇所には残す。

### 二項対比を直接表現へ変える

```text
変更前: これは単なる高速化ではなく、待ち時間のばらつきを抑える変更です。
変更後: この変更は待ち時間のばらつきを抑えます。
```

対比自体が論証上重要なら残す。

### 文長を内容へ合わせる

- 一文に主体、条件、例外、結果が重なれば分ける
- 短文が続いて劇的なリズムになっていれば結ぶ
- 一文だけの強調は、作者サンプルと場面に合えば残す

## 禁止する操作

### 架空の人間味

```text
禁止: 「正直」「実際に試したところ」「私は驚いた」を新しく足す
```

### 架空の具体性

```text
禁止: 「ある企業」を実在企業名へ置き換える
禁止: 「大幅に」を勝手な割合へ変える
```

### 意味の弱体化

```text
原文: 性能が向上した
禁止: 性能面にも関係している
```

### 意味の強化

```text
原文: 改善する可能性がある
禁止: 改善する
```

### 機能的な形式の破壊

- 手順を段落へ変える
- APIパラメータ表を散文へ変える
- 学術見出し番号を消す
- 比較項目を文章へ埋めて検索性を下げる

### 乱雑さの演出

- 誤字を足す
- 表記揺れを作る
- ランダムに口語を混ぜる
- 意味のない脱線を加える
- 文を不自然に途中で切る

## 修正の優先順位

同時に複数の問題がある場合は次の順で直す。

1. 内容の誤りと追加情報
2. 主体、確度、条件、因果
3. 場面に合わない語域
4. 空の前置きと結論
5. 構造の反復
6. 文と段落のリズム
7. 語彙と記号

表面だけを先に直すと、自然だが不正確な文章になりやすい。
